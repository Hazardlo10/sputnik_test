# Тестовое задание

Объединение чеков с магазинами, выборка двух магазинов и расчёт очередей на кассах.

## Что делается

1. В чеках (`store_checkout_queues`) магазин указан только как `store_uuid`. Справочник `store_stores` сопоставляет `store_uuid` и `store_id`. Джойн по `store_uuid` — получаем таблицу из 8 полей с нормальным `store_id`. Столбец `checkout_id1` из файла переименован в `checkout_id`.
2. Оставляем магазины 98451680 и 12864064 — 50 581 строка.
3. По выборке считаем, когда на кассах стояла очередь.

## Как считается очередь

Числа людей в очереди в данных нет — есть только время начала и конца обслуживания каждого чека. Операции на одной кассе не пересекаются (проверено), касса работает по одному клиенту. Поэтому про очередь судим по паузе между чеками:

- если пауза между концом одного чека и началом следующего маленькая, значит человек уже стоял, была очередь;
- если пауза большая, касса простаивала.

Ищем серии подряд идущих чеков на кассе, где каждая пауза не больше 60 сек (gaps and islands). Серия из 2 и более чеков — период очереди, от начала первого чека до конца последнего. Порог 60 с лежит в `Параметры!B1`, меняется — всё пересчитывается.

Порог взят от среднего обслуживания чека (около 53 сек): простой дольше этого значит подходить было некому.

При пороге 60 с: **7 599 периодов, 40 051 чек (79%), суммарно около 727 часов**. Самая длинная операция примерно 3 часа — выброс (не закрыли смену).
